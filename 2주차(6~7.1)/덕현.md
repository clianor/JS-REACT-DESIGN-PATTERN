# 06. 디자인 패턴의 유형

## 6.1 배경
디자인 패턴은 핵심 요소를 이름 짓고 추상화하여 재사용할 수 있는 객체 지향 설계를 만드는데 유용한 역할을 한다.
또한 디자인 패턴은 어떤 문제를 해결하는가에 따라 세 가지 유형으로 분류된다.

1) 생성 패턴
    1. 주어진 상황에 적합한 객체를 생성하는 방법에 중점을 둠.
    2. 객체 생성 방식이 프로젝트 복잡성을 증가시키는 문제를 해결하고자 함.
    3. ex) 생성자, 팩토리, 추상, 프로토타입, 싱글톤, 빌더 패턴.

2) 구조 패턴
    1. 객체의 구성과 객체 간의 관계를 인식하는 방법에 중점을 둠.
    2. 변경된 부분이 다른 부분에는 영향 없도록 만들고, 설계 목적에서 벗어난 부분을 개선하도록 도움.
    3. ex) 데코레이터, 퍼사드, 플라이웨이트, 어댑터, 프록시 패턴.

3) 행위 패턴
    1. 객체 간 커뮤니케이션을 개선하는 방법에 중점을 둠.
    2. 객체 간 커뮤니케이션 패턴을 감지하고 책임을 분배함으로써 커뮤니케이션의 유연성을 높이고 객체의 행위를 추상화 함.
    3. ex) 이터레이터, 중재자, 관찰자, 방문자 패턴

## 7.2 생성자 패턴
생성자란? 객체가 생성될 때 초기화하는 데 사용되는 메서드를 말한다.

자바스크립트에서 객체를 생성하는 세 가지 일반적인 방법은 아래와 같다.
```js
// 1. 객체 리터럴
const newObject = {};

// 2. Object.create() 메서드 사용
const newObject = Object.create(Object.prototype);

// 3. Object 생성자
const newObject = new Object();
```

## 7.3 모듈 패턴
모듈 패턴은 전통적인 소프트웨어 엔지니어링 분야에서 클래스의 캡슐화를 위해 처음 고안되었다.

### 모듈
모듈은 애플리케이션 아키텍처의 핵심 구성 요소이다.
코드 단위를 체계적으로 분리/관리하는 데 활용된다.

### 비공개
모듈 패턴은 비공개 요소를 클로저를 활용해 캡슐화 한다.
ES10(ES2019) 이전의 자바스크립트에서는 접근 제한자가 지원되지 않아, 함수 스코프를 활용해 비공개 개념을 구현 했었다.

### 모듈 패턴의 변형
- 믹스인 가져오기 변형
- 내보내기 변형

### 장점
1. 모듈 간의 의존성을 효과적으로 관리할 수 있다.
2. 전역 요소를 필요한 만큼만 노출하여 유지보수성을 높일 수 있다.
3. export로 노출한 값만 접근할 수 있도록 비공개를 지원한다.
4. 여러 의존성을 동시에 사용하면서도 이름 충돌을 피할 수 있어 코드를 안전하게 캡슐화할 수 있다.

### 단점
1. 공개 멤버와 비공개 멤버의 접근 방식이 서로 다르다.
2. 이후에 추가되는 메서드에서는 비공개 멤버에 접근할 수 없다.
3. 단위 테스트 시 비공개 멤버를 테스트할 수 없다.
4. 비공개 멤버에서 오류가 발생했을 때, 해당 멤버를 사용하는 모든 공개 메서드를 검토해야 하므로 긴급 수정이 어렵다.

## 7.4 노출 모듈 패턴
모든 함수와 변수를 비공개 스코프에 정의하고, 공개하고 싶은 부분만 포인터를 통해 비공개 요소에 접근할 수 있게 해주는 익명 객체를 반환하는 패턴이다.

### 장점
1. 코드의 일관성이 유지된다.
2. 공개 객체를 모듈의 가장 아래에 위치하게하여 가독성을 향상시킨다.

### 단점
1. 비공개 함수를 참조하는 공개 함수를 수정할 수 없다.

## 7.5 싱글톤 패턴
클래스의 인스턴스가 오직 하나만 존재하도록 제한하는 패턴입니다.

### 싱글톤 패턴의 적합성
- 클래스의 인스턴스는 정확히 하나만 있어야 하며 눈에 잘 보이는 곳에 위치시켜 접근을 용이하게 해야 한다.
- 싱글톤의 인스턴스는 서브클래싱을 통해서만 확장할 수 있어야 하고, 코드의 수정 없이 확장된 인스턴스를 사용할 수 있어야 한다.

### 단점
1. 싱글톤임을 파악하기 어렵다.
2. 테스트하기 어렵다.
3. 애플리케이션이 점점 커지면 올바른 실행 순서를 구현하기 어렵다.

### 7.5.1 리액트의 상태 관리
리액트로 개발하면 싱글톤 대신 Context API나 Redux 같은 전역 상태 관리 도구를 이용하여 개발할 수 있다.
싱글톤과 달리 이러한 전역 상태 관리 도구는 변경 불가능한 읽기 전용 상태를 제공한다.


## 7.6 프로토타입 패턴
이미 존재하는 객체를 복제해 만든 템플릿을 기반으로 새로운 객체를 생성하는 패턴이다.
프로토타입 패턴은 프로토타입의 상속을 기반으로 한다.

### 장점
1. 상속을 구현하는 쉬운 방법이다.
2. 객체 내에 함수를 정의할 때 복사본이 아닌 참조로 생성되어 성능을 챙길 수 있다.

```js
class Car {
  protected name: string;

  constructor(name: string) {
    this.name = name;
  }

  setName(name: string): void {
    this.name = name;
  }

  getName(): string {
    return this.name;
  }
}

const original: Car = new Car('Sonata');
console.log(original.getName());

const cloned: Car = Object.create(original);
cloned.setName('Avante');
console.log(cloned.getName());
```
